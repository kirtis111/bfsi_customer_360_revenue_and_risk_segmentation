# Customer 360 + Revenue & Risk Segmentation

> A production-style banking analytics project built in PostgreSQL and Power BI.
> This project demonstrates the full data analyst workflow: raw data → cleaning → modelling → segmentation → reporting.

---

## What This Project Does

A Canadian retail bank wants a unified view of its customers to identify high-value relationships, detect at-risk borrowers, and prioritise cross-sell outreach. This project delivers that end to end, using only SQL and Power BI.

**The headline finding:**
*Top 20% of customers (40 people) hold 75.8% of total deposits - and balance alone is not a reliable proxy for customer value.*

## Setup: Run in This Order

### Prerequisites

- PostgreSQL 15+ with a database named `customer360`
- Python 3.9+ with `faker`, `pandas`, `numpy` installed
- Power BI Desktop (for dashboard)

### Step 1 - Generate raw data

```bash
pip install faker pandas numpy
python generate_data.py
# Outputs: 00_data/raw_customers.csv, raw_accounts.csv,
# raw_transactions.csv, raw_loans.csv
```

### Step 2 - Create tables

```sql
-- In pgAdmin or psql:
\i 01_schema/01_create_tables.sql
```

### Step 3 - Load raw CSVs into staging

```sql
-- Update the four file paths in 02_seed_data.sql first, then:
\i 01_schema/02_seed_data.sql
-- Verify: all four PASS rows in the row-count check
```

### Step 4 - Clean the data (SQL only)

```sql
\i 01_schema/03_clean_raw_data.sql
-- Verify: all checks in Section 5 return PASS
```

### Step 5 - Create views

```sql
\i 02_views/core/customer_base_view.sql
\i 02_views/core/transaction_enriched_view.sql
\i 02_views/business/customer_360_view.sql
\i 02_views/business/monthly_trends_view.sql
```

### Step 6 - Run business logic

```sql
-- Run each file sequentially in pgAdmin:
\i 03_business_logic/segmentation_query.sql    -- runs the UPDATE too
\i 03_business_logic/risk_tagging_query.sql
\i 03_business_logic/top_customer_analysis.sql -- creates TEMP TABLE
\i 03_business_logic/cross_sell_opportunities.sql -- creates TEMP TABLE
```

### Step 7 - Run validation

```sql
-- All 22 + 26 + 5 checks should return PASS:
\i 06_validation/data_quality_checks.sql
\i 06_validation/null_checks.sql
\i 06_validation/duplicate_checks.sql
```

### Step 8 - Connect Power BI

1. Open Power BI Desktop
2. **Get Data → PostgreSQL database**
3. Import `powerbi_prep_query.sql` → name table `pbi_customer_master`
4. Import second query → name table `pbi_monthly_trends`
5. Build visuals using the field groups (`bal_`, `tx_`, `loan_`, `risk_`)

All data is **synthetic** - generated by `generate_data.py` using Faker (Canadian locale) and a Pareto distribution for account balances. No real customer data is used.

| Table        | Rows   | Notes                                         |

## Key Findings

### 1. Deposit Concentration Risk

Top 20% of customers (40 people) hold **75.8% of total deposits** (CAD 755,808 of CAD 996,871). The top 10% alone hold 58.8%. This Pareto concentration means the loss of a single High Value customer removes more deposit value than losing 20 Low-tier customers.

### 2. Balance ≠ Value

Only **4 of the top-20 customers by balance** also appear in the top-20 by composite LTV score (balance 40% + transaction volume 30% + interest revenue 30%). Hidden Gems - customers with modest deposits but large loan portfolios - are systematically undervalued by balance-only dashboards.

### 3. 15.7% of the Loan Book Is at Risk

23 customers (10 defaulted, 13 delinquent) hold **CAD 3,123,061** in outstanding loans. At-risk customers carry above-average loan balances, making their exposure disproportionate to their headcount share.

### 4. 66 Customers Have No Retirement Product

One-third of the portfolio holds neither an RRSP nor a TFSA - the largest single cross-sell gap. Priority targets are High Value and Medium tier customers aged 35–54, scored with a weighted urgency model.

### 5. Channel Distribution Is Balanced

Branch (25.4%), Online (25.3%), Mobile (25.0%), ATM (24.3%). Multi-channel engagement is healthy. Cross-sell outreach should route by each customer's preferred channel rather than defaulting to digital.

### 6. BC and NS Punch Above Their Weight

British Columbia (31 customers, CAD 295K deposits) and Nova Scotia (25 customers, CAD 212K) outperform Ontario (31 customers, CAD 106K) by 2-3× in average balance per customer.
